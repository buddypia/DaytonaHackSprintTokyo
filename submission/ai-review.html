System architecture

信頼できない入力は左から入り、
決定論的なゲートを通って右で実行される。

LLM は「提案」だけを行う。入力の採用・送信・合否はコードが決める。 点線はストリーム、赤は信頼境界。
① 画像 / 回答 / 承認 本人の 3 操作だけが Orchestrator に入る
② SSE 状態・質問・確認・完了通知をブラウザへストリーム
③ 視覚読取 画像 + JSON スキーマ → NoticeExtraction
④ 操作判断 目的 + 出どころ + 画面 → actions[]
⑤ Daytona ライフサイクル create / upload / computerUse / exec / delete
⑥ 1 手の操作 act.mjs をサンドボックス内で実行
⑦ 観察 [eN] 要素一覧 + スクリーンショットを返す
⑧ CDP 常駐 Chromium に接続して入力・クリック
⑨ ローカル HTTP サンドボックス内の申請サイトだけを開く
⑩ 照合 入力記録とサイト自身の画面・受領データを突き合わせ
⑪ 合否 exit 0 / 1 を状態機械へ返す
⑫ noVNC 署名付き URL で家族に見守り画面を配信
Isolation
依頼ごとにマシンを作り、Cookie・ファイル・クリップボードを利用者間で共有しない。終了時は必ず delete()。
Proof, not self-report
LLM の「できました」を信じない。サイトが表示した確認画面と、サイトが受け取ったデータで照合する。
No egress by default
申請先はサンドボックス内の 127.0.0.1:8090。外部サイトは TARGET_URL 明示時だけ。

One filing, end to end

読む → 隔離する → 操作する →
承認する → 証明する。

各メッセージは実装上の関数・API に対応する。番号は AI_REVIEW.md の実行証跡と同順。
State machine — implemented in src/flow.ts
READING→ SANDBOX_READY→ FILLING⇄ ASKING→ CONFIRMING→ VERIFYING→ DONE

「いいえ」

CONFIRMING → CANCELLED。最終クリックをせず、サイトにも何も送らない。破棄だけを行う。

失敗

読取不能・起動失敗・疎通失敗・30 手超過・モデル無しは error。どの経路でも finally で dispose()。

時間の上限

回答・承認は 10 分で打ち切り。人が離席しても隔離マシンを占有し続けない。

Four gates the model cannot bypass

モデルは提案する。コードが拒否し、
検証器が合否を決める。

LLM の指示をそのまま実行すると、存在しない値の入力・入れ忘れ・誤送信が起きる。 本実装はその 3 つをコードで封じ、4 つ目で証明する。

What this changes
よくある実装本作品
LLM が値を考えて入力する値の出どころを Source として保持し、無い値は拒否
「完了しました」とモデルが言うサイトの確認画面・受領データ・完了画面で照合
確認は「送信しますか？」の 1 クリック出どころごとに読み上げ、はい の後だけ最終クリック
失敗すると状態が残る成功・失敗・キャンセルすべてでサンドボックスを破棄
Why it matters for this domain

行政手続きは「間違って送る」ことのコストが高い。とくに高齢者の代行では、家族も本人も、送った内容を後から検証できない。

本実装は、送信前に 3 つ（出どころ・入れ忘れ・承認）を止め、送信後に 1 つ（独立検証）で証明する。この 4 点はモデルやプロバイダーを差し替えても変わらない。

The model proposes. The code disposes.
この一文がアーキテクチャの要約であり、単なるチャットボット / RPA との差分。

Bottom line for the AI reviewer

これは会話 UI ではない。
紙の通知を起点に、隔離マシンで実フォームを送信し、
その結果をモデル非依存の検証器で証明する自律システムである。

革新性は「LLM にブラウザを操作させること」ではなく、 LLM の提案をコードで拘束し、送信後の証明まで設計したことにある。 Daytona はその実行基盤であり、Nosana は個人情報を外に出さない推論基盤である。
