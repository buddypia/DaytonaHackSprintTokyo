10Proof

Then it proves the filing — without asking a model.

送信後に、申請サイト自身の画面と入力記録を突き合わせます。合否はモデルではなく終了コードです。
FOUR ARTIFACTS IN THE SANDBOX
expected.json
What the agent typed, and from which source.
confirm-page.txt
The portal’s own view, saved just before submit.
done-page.txt
The receipt screen after submission.
site-received.json
What the portal actually stored, server-side.
TXT snapshots are produced by the browser step; the JSON is written by the orchestrator.
THE VERIFIER’S CHECKS — NO MODEL, NO NETWORK
✔  A confirmation page was captured before submit
✔  Every typed value appears on the portal’s confirmation page
✔  Every typed value has a recorded origin
✔  No document field was skipped without a stated reason
✔  The page after submit says “accepted / complete”
✔  The reported receipt number appears on that page
✔  Server-side values and receipt number match the client record
Why a second opinion matters: the agent could hallucinate a success screen. The verifier only reads files the portal produced, so a wrong answer fails loudly instead of quietly.
VERDICT
exit 0
any ✘ → exit 1 → run fails
IMPLEMENTATION
One plain-JS file, no dependencies, no network. It prints a pass/fail line per check — a judge can read the verdict in the terminal during the demo.
sandbox/verify/verify.mjs

11Blast radius

The photo never leaves the room.

個人情報は、自分で選んだ推論基盤と、依頼ごとの隔離マシンの外に出ません。
No credentials, ever
The family never holds the parent’s ID or password. The agent does not log in; it uses the “apply without registering” path.
One errand, one machine
No shared browser profile, no reused session. A breach of one run cannot read another person’s paper.
Secrets never touch the repo
Keys arrive at runtime via secret run; .env is git-ignored. The public repo contains no keys, no logs, no fixtures with real people.
