07ループ

手を選ぶのはモデル。
合法を決めるのはコード。

The model picks the move; the code decides what is legal. Guards live where a prompt cannot reach.
1 · 出典がなければ入力しない
アクションを破棄
すべての入力・選択には fromが必要で、どの記録から来たかを指す。出典のない値はブラウザに届かない。
2 · 未入力は残さない
送信を遮断
書類の各項目は、入力するか「該当なし」と理由を付けて宣言する。未解決集合が空になるまで、最後のボタンは存在しない。
3 · 最後のボタンは人
先に確認
A submit アクション、または最終申請に見えるラベルのクリックは、読み上げを起こして明示的な「はい」を待つ。
4 · 上限は構造で決まる
安全に停止
30ターン、3質問、待機10分。上限を超えたらサンドボックスを破棄し、実行は失敗として報告する。完了とは報告しない。

10証明

そして申請を証明する。モデルには聞かない。

After submit, the receipt page and the input record are compared. The verdict is an exit code.
サンドボックスに残る4つの成果物
expected.json
何を、どこから入力したか。
confirm-page.txt
送信直前に保存した、ポータル自身の画面。
done-page.txt
送信後の受付画面。
site-received.json
ポータルがサーバ側で実際に保存した内容。
TXT はブラウザ操作が生成し、JSON はオーケストレータが書き出す。
検証器の7チェック — モデルなし・ネットワークなし
✔  送信前に確認画面が保存されている
✔  全入力値がポータルの確認画面に出ている
✔  全入力値に出典が記録されている
✔  理由なく飛ばされた書類項目がない
✔  送信後の画面が「受付・完了」を示す
✔  報告した受付番号がその画面にある
✔  サーバ側の値と受付番号がクライアント記録と一致
なぜ二重チェックか：エージェントは成功画面を幻覚しうる。検証器はポータルが作ったファイルしか読まないので、誤りは静かに通らず、大きく落ちる。
判定
exit 0
✘ が1つでも → exit 1 → 失敗
失敗は隠さず見せる：実行は「送信済みだが不整合」で終わり、✘ 行を添える。「完了」とは報告しない。
実装
素のJS1ファイル。依存なし、ネットワークなし。チェックごとに合否を1行で出し、デモ中に審査員がターミナルで判定を読める。
sandbox/verify/verify.mjs
成功条件は、モデルが書いた文ではなく、ポータルが書いたファイル10 / 15

14審査基準へ

審査は4点。根拠を出す。

Four rubric axes, answered with implementation, measurement and reproduction.
01
完成度
実装済み・モックなし
1回の実行が 写真 → 説明 → 実サンドボックス → 入力 → 本人承認 → 送信 → 検証 exit 0 → 受付票 → 破棄 まで通る。
▸ npm test — 検証器とガードの単体テスト
▸ 対象ポータルに自治体手続き5種
▸ 失敗経路：中止・読取失敗・タイムアウト・到達不能
02
革新性
監査できる自律性
多くのエージェントは「何を作ったか」で評価される。本作は「何を証明できるか」で評価される。全値が出典を持ち、証明を確かめるのはモデルではなくプログラム。
▸ 出典なしの値をコードで拒否
▸ 黙って飛ばさず「該当なし」と宣言
▸ 承認者には出典ごとに値を提示
03
課題解決
デモ用の見せかけではない
ボトルネックは手紙の理解ではなく、そのあとの20分の入力。その労力はいま、電話越しに、親のパスワードを使って、成人した子に降りかかっている。
▸ ペルソナ2人・受け渡し1回・人の操作3つ
▸ 実際の自治体ポータル風の画面で動く
▸ 価値の単位は期限であって、メッセージではない
