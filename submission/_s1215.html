Nosana
SPONSOR · INFERENCE
An OpenAI-compatible endpoint, so the same code runs on Nosana GPUs, on your own Vertex project, or on a laptop Ollama. The default for a privacy-sensitive deployment is Nosana.
Vision — reads the notice into a fixed JSON shape: type, deadline, three-line summary, person fields with source text + confidence.
Policy — decides the next browser action each turn, at temperature 0.
Latency hedge — if no answer in 6s, a second identical request is sent; the first reply wins.
Split roles — read a notice on Nosana, drive the browser on Vertex; one env var each.

4つの審査基準に対して、実装・実測・再現手段で答えます。
01
Completeness
SHIPPED, NOT MOCKED
A single run goes photo → explanation → live sandbox → typed form → human approval → submission → verifier exit 0 → receipt → teardown.
▸ npm test — verifier + guardrail unit tests

02
Innovation
AUDITABLE AGENCY
Most agents are judged on what they produce. Ours is judged on what it can prove: every value carries its origin, and the proof is checked by a program, not the model.
▸ Code-level refusal of unsourced values
▸ “Declared not-applicable” instead of silent omission
▸ The approver sees values grouped by origin
03
Real-life problem solving
NOT A DEMO-GRAM
The bottleneck is not understanding the letter — it is the 20 minutes of typing after it. That labour currently lands on an adult child, by phone, with the parent’s password.
▸ Two personas, one handoff, three human actions
▸ Works on real municipal portal layouts (not a toy form)
▸ Deadlines are the unit of value, not messages
04
Sponsored product usage

Daytona is the execution substrate: nine SDK surfaces, one sandbox per errand, deleted at the end. Nosana is the privacy-safe inference path for documents full of personal data.
