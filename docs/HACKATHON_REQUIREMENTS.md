# Daytona HackSprint Tokyo — ハッカソン要件定義

- **イベント名**: Daytona HackSprint Tokyo（ハッカソン東京）
- **公式ページ**: <https://luma.com/daytonatokyo1115>
- **開催日時**: 2026年11月15日（日）14:00 – 18:00 JST
- **共催**: [AI Builders](https://theaibuilders.dev/) / [Daytona](https://daytona.io/)（タイトルスポンサー）
- **スポンサー**: [Nosana](https://nosana.io/)

---

## 1. テーマと必須要件

単純なチャットボットではなく、ライブデータの収集、ワークフローの自動化、インフラの管理、大規模なデプロイを本番環境で連携して行う自律型AIシステム・本番グレードのAIアプリケーションのプロトタイプを構築する。

- **スポンサープロダクトの統合（必須）**: プロジェクトにはスポンサーのプロダクトを統合する必要がある。実用的なデモを時間内に出荷する手段として、Daytona サンドボックスの活用が推奨されている。
- **最低限の実用的な製品（MVP）の出荷**: 当日のライブデモ（各チーム2分）で実際に動作するプロトタイプを提示する。

---

## 2. 対象スポンサープロダクト

### Daytona（タイトルスポンサー）— <https://daytona.io/>

自律型AIエージェント向けに構築された、安全で弾力的なクラウドインフラ。各AIエージェントに分離されたサンドボックス（独自のカーネル、ファイルシステム、ネットワークスタック、vCPU、RAM、ディスクを備えた完全なコンピュータ環境）を提供し、コードの安全な実行、パッケージ導入、サーバー起動、本番環境への出荷を可能にする。

- **サブ秒のサンドボックス起動**: 約 90〜200 ミリ秒でコード実行可能な状態になり、エージェントの処理フローを止めない。
- **完全なマシンセマンティクス**: パッケージのインストール、プロセス管理、Git 操作、コードのコンパイル、ブラウザやゲームの実行がすべてサンドボックス内で完結する。
- **ネイティブ SDK + MCP**: Python、TypeScript、Go、Ruby、Java の各 SDK に加え、任意のエージェントフレームワークから Daytona をツールとして操作できる MCP サーバーを提供する。
- **並列エージェント対応**: ファンアウト型のエージェントワークフロー、モデル評価、バッチコード実行向けに、数千のサンドボックスを同時起動できる。
- **オープンソース（AGPL）**: 提供される Helm チャートを用いた Kubernetes 上でのセルフホスト、またはマネージドの Daytona Cloud を利用できる。

### Nosana（スポンサー）— <https://nosana.io/>

高負荷なAIワークロードに対してオンデマンドで GPU アクセスを提供する分散コンピューティングネットワーク。大規模な基盤モデルの学習・ファインチューニングから、本番エージェントやアプリケーション向けの低遅延リアルタイム推論までを対象とする。

## 3. 審査基準と審査方式

### 審査基準（4項目）

1. **完成度（Completeness）**: 最低限の実用的な製品（MVP）を出荷したか。
2. **革新性（Innovation）**: 製品のアイデアは革新的か。
3. **現実の問題解決（Real-Life Problem Solving）**: 現実の問題を解決しているか、市場に実際の課題があるか。
4. **スポンサープロダクトの活用（Sponsored Product Usage）**: スポンサーのプロダクトを統合したか。

### 審査方式（二段階審査）

参加規約に基づき、以下の二段階で審査が行われる。

- **一次審査（AI審査）**: 応募プロジェクト数が多いため、一次審査には AI を使用する（リバースエンジニアリング防止のため審査コードの詳細は非公開）。
- **二次審査（人間による審査）**: 人間の審査員が審査を行う。ライブデモの持ち時間は**各チーム2分**。

## 5. 参加・チーム編成・クレジット規定

- **参加対象**: チュートリアルの先へ進み、実際に動くプロダクトを構築したい開発者、AIエンジニア、ファウンダー、学生。
- **チーム人数**: **ソロ（1人）**または**最大6名以下のチーム**。
- **チーム編成ルール**: チーム結成はワークショップ後に**当日会場でのみ実施**される。参加登録はチーム単位ではなく**個人単位**であり、Luma 上で `Going`（参加確定）ステータスの参加者のみ会場へ入場・参加できる（`Pending` / `Waitlist` のメンバーは参加不可）。
- **クレジット配布と賞品**:
  - **参加者全員**: ハッカソン中の開発に利用できるスポンサークレジットが付与される。
  - **受賞チーム**: 賞品としてスポンサークレジットを共有する。
