# おまかせ手続き（Omakase Tetsuzuki）

> 届いた通知を撮るだけ。AI が隔離されたパソコンを代わりに操作して（Computer Use）、お年寄りの手続きを最後まで済ませる。

Daytona HackSprint Tokyo（2026-11-15）の出品作品です。概要は [`BRIEF.md`](./BRIEF.md)、要求は [`PRD.md`](./PRD.md)、設計は [`SPEC.md`](./SPEC.md) にまとめています。

## 解決する課題

役所から届く通知は文面が難しく、高齢者は「何を、いつまでにするか」が分からないまま期限を過ぎてしまいます。電子申請が増えても、画面を操作できなければ使えません。今は離れて暮らす家族が電話で内容を聞き取り、親の ID とパスワードを預かって代わりに申請しています。

## できること

1. 通知・案内・届出書の記入例・空欄の様式など、どんな書類でも撮影して送ると、「何の書類か・いつまでに・何をするか」を3行の大きな字と音声で説明します。同時に、書類に書かれたご本人の情報（氏名・生年月日・住所・電話番号など）を、書類上の原文と一緒に取り出します（[`src/reader.ts`](./src/reader.ts)）。記入例の値は見本として扱い、本人の値としては使いません。
2. 依頼ごとに画面付きの隔離マシン（Daytona サンドボックスの Computer Use）を起動し、そのデスクトップ上のブラウザで電子申請サイトを開きます。既定は、**隔離マシンの中に立ち上げる検証用の申請サイト**です（下記）。操作エージェント（[`src/operator.ts`](./src/operator.ts)）は画面を `[eN]` 付きの文字として読み、次の操作（入力・選択・クリック）を LLM が1手ずつ決めます。手順を作り込んだスクリプトではないので、初めて見るフォームでも進めます。次の3つはモデル任せにせず、コードで守ります。
   - 入力する値には出どころ（書類の項目・ご本人の回答・ご家族の設定）が必要で、出どころの無い値は入力しません。
   - 書類から読んだご本人の情報は、すべて入力するか「この手続きには欄が無い」と理由付きで申告するまで送信させません。
   - 最後の申込ボタンは、本人の承認を得てから押します。家族はデスクトップをライブ（noVNC、見るだけ）で見守れます。
   - 既定の申請先は、検証用の申請サイト [`sandbox/site/server.mjs`](./sandbox/site/server.mjs) です。架空の「ひばり野市 電子申請サービス」を再現したポータルで、トップ・手続き一覧・検索・お知らせ・よくある質問・利用ガイド・申込状況の照会と、5つの手続き（水道料金の口座振替、粗大ごみ収集、住民票の写しの郵送請求、学童保育の利用申込、受付終了の商品券申込）があります。エージェントはトップから目的の手続き（既定は「水道料金・下水道使用料の口座振替申込」）を探して開きます。各手続きの画面は手続き説明 → 利用規約への同意 → 入力 → 確認 → 完了（受付番号）で、入力に誤りがあるとエラーを出します。隔離マシンの中の `127.0.0.1:8090` で起動し、外には何も送りません。そのため、実在のサイトに申し込みや契約が届くことはありません。また、どの隔離マシン（Daytona・GCP・Docker）でも、外向き通信の制限に関係なく同じように動きます。`TARGET_URL` を指定したときだけ、外のサイトを開きます。
3. 書類からは分からない項目だけを、ご本人に質問します。選択肢はボタンか声で、それ以外は文字で答えられます。
4. 申請サイトの確認画面まで進んだら、入力内容を出どころごとにまとめて読み上げ（例: 生年月日は「昭和 23 4 12」）、「はい」と言われてから送信します。「いいえ」なら何も送信しません。
5. 同じ隔離マシンで検証スクリプトを動かします。入力した値がすべて申請サイト自身の確認画面に出ていること、検証用サイトが実際に受け取った内容に入っていること、すべての値に出どころがあること、書類の情報に入れ忘れが無いこと、完了画面と整理番号を確かめます（`exit 0` で合格）。
6. 整理番号をご本人に、完了の通知をご家族に届け、隔離マシンを破棄します。

## Daytona と Nosana の統合箇所

| スポンサー | ファイル | 役割 |
|---|---|---|
| **Daytona** | [`src/sandbox.ts`](./src/sandbox.ts)（`DaytonaRunner`） | 依頼ごとにサンドボックスを作成し、`sandbox/` 一式を配置します。`computerUse.start()` でデスクトップを起動し、その画面上のブラウザ（Playwright の Chromium、CDP で常駐）で実在の申請サイトを開きます。操作エージェントの1手ごとに `process.executeCommand` で `agent/act.mjs` を実行して画面を読み、操作します。`getSignedPreviewUrl(6080)` の noVNC で家族にライブ配信します。検証スクリプトを実行したあと、サンドボックスを破棄します |
| **Nosana** | [`src/ai.ts`](./src/ai.ts)（`nosana()`）→ [`src/reader.ts`](./src/reader.ts)・[`src/operator.ts`](./src/operator.ts) | GPU 上の OSS 視覚モデルで通知を読み取り、操作エージェントの次の一手を決めます。個人情報を外部の商用 API に送りません |

推論と隔離実行はプロバイダーとして切り替えられます（`AI_PROVIDER` = `nosana` / `vertex`、`SANDBOX_PROVIDER` = `daytona` / `gcp` / `docker` / `local`）。`gcp` は Compute Engine の VM 上に、依頼ごとに同じ構成のデスクトップのコンテナを作って破棄します（[`src/sandbox.ts`](./src/sandbox.ts) の `GcpRunner`）。`docker` は Daytona の Computer Use と同じ構成（Xvfb + xfce4 + x11vnc + noVNC）のデスクトップを [`desktop/Dockerfile`](./desktop/Dockerfile) でローカルに再現したもので、Daytona のキーが無くても「画面付きの隔離マシンの中で、エージェントが実在の申請サイトを操作する」全工程を実際に動かせます。

モデルの応答が遅れたとき（数十秒の外れ値がある）は、6秒待って同じ依頼をもう1本出し、先に返った方を使います（`AI_HEDGE_MS`）。

サンドボックス内で動くプログラムは次の4本です。

- [`sandbox/agent/browser.mjs`](./sandbox/agent/browser.mjs): サンドボックス内で常駐するブラウザ（画面があればそこに表示）
- [`sandbox/agent/act.mjs`](./sandbox/agent/act.mjs): 1手の操作をして、画面を `[eN] 種類 "名前"` の一覧とスクリーンショットで返します（OpenMausBot の aria スナップショット + ref の方式）
- [`sandbox/site/server.mjs`](./sandbox/site/server.mjs): 検証用の申請サイト（外には何も送らない。受け取った内容を検証用に残す）
- [`sandbox/verify/verify.mjs`](./sandbox/verify/verify.mjs): 検証。モデルを使わずに、申請サイトの確認画面・完了画面とエージェントの入力記録を照合し、終了コードで合否を返します

## 起動方法

Node.js 23.6 以上が必要です（TypeScript をビルドせずにそのまま実行します）。

```bash
npm install
npm run desktop:build             # 初回のみ。画面付きの隔離マシン（Docker Desktop が必要）
npm start                         # http://localhost:8787
```

`desktop:build` 済みなら、キーが無くても Docker デスクトップで動き、見守り画面に隔離マシンのデスクトップがライブで映ります。

GCP で動かす場合（Compute Engine の VM 1台。e2-standard-4、使わないときは停止）:

```bash
npm run gcp:up                    # API の有効化・VM 作成・SSH 鍵の登録・イメージのビルド（2回目以降は起動だけ）
SANDBOX_PROVIDER=gcp npm start
npm run gcp:down                  # 使い終わったら停止（停止中はディスク代だけ）
```

アプリ本体も同じ VM に載せて、自分の IP からだけ HTTPS で開けるようにする場合:

```bash
npm run gcp:deploy                # https://<IP>.sslip.io/ で起動（Caddy + Let's Encrypt。443 は今の自分の IP だけ許可）
                                  # 検証用の申請サイトもデモ用に https://site.<IP>.sslip.io/ で配信（同じく自分の IP だけ）
npm run gcp:allow                 # 回線が変わったら（会場の Wi-Fi など）、443 の許可を今の IP に付け替える
```

80 番は証明書の取得と HTTPS への転送だけなので、全体に開けています。推論は VM のサービスアカウントで Vertex AI を呼ぶので、VM にキーは置きません。

画面の「見本の請求書で試す」を押すと、デモ用の水道料金の請求書（[`fixtures/bill.png`](./fixtures/bill.png)）をモデルが読み、検証用の申請サイトで最初から最後まで動きます。請求書は架空の人物・番号で、実物の納付書と同じ作り（お客様番号・検針・内訳・きりとり線の納付書）です。机の上でスマホ撮影した写真に見えるように加工しています。画像生成 AI は文字や数字を崩すので使わず、[`fixtures/bill.html`](./fixtures/bill.html) から `npm run make:notice` で作ります。書類から読めないのは口座の情報だけなので、ご本人への質問は金融機関・支店名・口座番号の3つです。

裏側の説明には [`/ops`](http://localhost:8787/ops) を別のタブで開きます。読み取り AI・操作エージェント・オーケストレーター・サンドボックス内のブラウザと検証・検証用の申請サイトがどの順に何を渡しているかを、Daytona サンドボックスの枠と一緒にフロー図で見せます。実行が終わったあとも「最初から」で 1x / 4x / 16x の再生ができます。

### 実行モード

設定は `.env`（[`.env.example`](./.env.example) をコピー。git には入りません）に書きます。モデル（`vertex` か `nosana`）と隔離マシン（Daytona か Docker デスクトップ）が必要です。どちらかが無いときは、黙って代わりのもので動かさずにエラーで止めます。

| 環境変数 | 値 | 内容 |
|---|---|---|
| `AI_PROVIDER` | `vertex` | Vertex AI の Gemini で通知を読み、操作を決める。`GCP_PROJECT`、`GCP_ACCOUNT`（任意）、`VERTEX_MODEL`（既定 `google/gemini-3.5-flash`）。認証は `gcloud auth login` 済みのアカウントを使い、キーは不要 |
| | `nosana` | Nosana 上のモデルで読み、操作を決める。`NOSANA_BASE_URL`（OpenAI 互換の `/v1`）、`NOSANA_MODEL`、`NOSANA_API_KEY`。Ollama なども指定できる |
| `OPERATOR_AI_PROVIDER` | `nosana` / `vertex` | 操作エージェント側の推論プロバイダー（省略時は `AI_PROVIDER` と同じ）。通知画像の読み取りだけを Nosana で行い、ブラウザ操作を Vertex AI で動かすハイブリッド構成に使える |
| `SANDBOX_PROVIDER` | `daytona` | Daytona サンドボックス（Computer Use の画面付き）で動かす（`DAYTONA_API_KEY` が必要。キーがあるときの既定） |
| | `gcp` | GCP の VM（`npm run gcp:up` で用意）に依頼ごとのコンテナを作って動かす。Docker の操作は SSH で転送した VM の docker.sock 越し、画面は SSH トンネル越しの noVNC。`GCP_PROJECT` / `GCP_ACCOUNT` / `GCP_VM` / `GCP_ZONE` |
| | `docker` | ローカルの Docker デスクトップで動かす（`npm run desktop:build` 済みのときの既定） |
| | `local` | ローカルの子プロセスで同じスクリプトを動かす（**隔離なし・開発用**。明示したときだけ使い、黙ってこれに落ちることはない） |
| `OMAKASE_SNAPSHOT` | スナップショット名 | ブラウザを導入済みのスナップショットから Daytona サンドボックスを起動する |
| `TARGET_URL` / `TARGET_NAME` | URL / 名前 | 申請先の手続き（既定は隔離マシン内の検証用サイト。指定すると外のサイトを開き、見本の画像は介護保険の通知になる） |
| `CONTACT_EMAIL` | メールアドレス | ご家族の連絡先。申請先が連絡先を求めたときに使う（未設定ならご本人に質問する） |

通知を読めなかったときは、エラーで止めます。別の通知の値で申請しないためです。

キーはファイルに書かず、実行時に渡します。

```bash
secret run DAYTONA_API_KEY -- npm start
```

## テスト

```bash
npm test
```

検証スクリプトと操作エージェントの決まりごと（出どころの無い入力をしない・入れ忘れたまま送信しない・承認なしに最後のボタンを押さない）の単体テストを実行します。

モデルと隔離マシンを使う通し確認は、明示したときだけ実行します。見本の請求書で検証用サイトに申し込み、「はい」なら送信して `exit 0` と受付番号、「いいえ」なら何も送信しません。外のサイトには何も送りません。

```bash
E2E=1 SANDBOX_PROVIDER=docker npm test   # gcp でも可
```

## 制約

- 既定では、隔離マシンの中の検証用サイトだけを操作します。実在の手続きには送りません。`TARGET_URL` で外のサイトを指定する場合も、自治体が「誰でも何度でも試せる」と公開している体験用の手続き（例: 佐倉市「[電子申請 体験](https://www.city.sakura.lg.jp/soshiki/joho_system/johoka/19743.html)」）に限ってください。
- Daytona の Tier 1/2 は外向き通信が許可リストに限られます。既定の検証用サイトはマシンの中にあるので影響を受けません。`TARGET_URL` で外のサイトを指定して届かないときは、起動時に「届きません」と表示して止まります。
- 署名や本人確認（マイナンバーカード）が必要な手続きは対象外です。
- Vertex AI（Gemini）での読み取りと操作、Docker デスクトップと GCP（asia-northeast1）での通しは、実機で確認済みです。佐倉市の体験手続きでは整理番号の取得まで、検証用サイトでは受付番号の取得と照合 `exit 0` まで確かめました。Daytona と Nosana は、キーが手元に無いためまだ実機で確かめていません。
